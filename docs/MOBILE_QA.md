# MOBILE_QA.md — Чек-лист приёмки мобильной версии

Документ фиксирует, **как проверять мобильную версию** AirBridge Landing и **что считается
дефектом**. Составлен по: WCAG 2.2 (SC 2.5.8 Target Size, 1.4.3 Contrast, 1.3.2 Meaningful
Sequence), web.dev «Responsive web design basics», Front-End-Checklist (GitHub),
Adrian Roselli «Tables, CSS Display Properties, and ARIA».

## 1. Как запускать проверку

```powershell
# локальный сервер
python -m http.server 8085
# автоматические проверки
python scripts/check_site.py
python scripts/fact_index.py
node --check assets/js/main.js
```

Ручные инструменты:
- **DevTools → Device Toolbar**: 360×780, 390×844, 414×896, 768×1024, 1024×768.
- **Lighthouse → Mobile** (категории Accessibility / Best Practices / SEO).
- **Performance → Record** (LCP, CLS, INP).
- Реальные устройства/эмуляторы: iPhone (Safari), Android (Chrome), Samsung Internet.

## 2. Обязательные критерии (блокирующие)

### 2.1 Геометрия
- [ ] **Нет горизонтального скролла**: `document.documentElement.scrollWidth === clientWidth`
      на 360 / 390 / 414 / 768.
- [ ] **Таблица сравнения не требует свайпа**: на ≤720px она превращается в карточки
      (`thead` скрыт, `display:block`), а не в горизонтальную прокрутку.
- [ ] **Ни один блок не «вылезает»**: проверить `getBoundingClientRect().right <= clientWidth`.
- [ ] **Контент не обрезан**: длинные строки переносятся, а не обрезаются `overflow:hidden`.

### 2.2 Тач-таргеты (WCAG 2.2 SC 2.5.8)
- [ ] Все интерактивные элементы ≥ **24×24 CSS px**; для важных действий — **44×44**.
- [ ] Между соседними таргетами есть зазор (иначе нужен интервал 24px по SC 2.5.8).
- [ ] Точки слайдера: контейнер 24×24, визуальный диск 10px (не увеличивать диск до хит-зоны).

### 2.3 Типографика и читаемость
- [ ] Строка лида/текста — **45–75 символов** на 390px (не «одно слово в строке»).
- [ ] Минимальный размер основного текста — **16px** (мелкие подписи ≥ 12px).
- [ ] Межстрочный интервал 1.4–1.6; заголовки не рвутся посередине слова.
- [ ] Текст секций на мобильных выровнен по левому краю (`text-align: left`).

### 2.4 Контраст (WCAG AA)
- [ ] Текст на светлом фоне: оранжевый акцент — только `--cdc-orange-ink` (#b5470a) или
      `--cdc-orange-display` (#f05f00) для крупного текста; **не** `#ff751f` для мелкого текста.
- [ ] Текст на оранжевых плашках — `--cdc-btn-ink` (#141414), не белый.
- [ ] Мелкие подписи (`note`, `caption`, `label`) ≥ 4.5:1; крупный текст ≥ 3:1.
- [ ] Проверка: Lighthouse → Accessibility → `color-contrast` = 1.0.

### 2.5 Медиа
- [ ] Hero: на ≤768px загружается `hero-pendulum-mobile.mp4`, на десктопе — полный файл.
- [ ] Постер hero (`hero-poster.jpg`) имеет `fetchpriority=high` (preload в `<head>`).
- [ ] Слайдеры решений **не грузят все фото сразу**: при первом открытии — 2 кадра на слайдер,
      остальные — по мере показа.
- [ ] Все изображения имеют `alt`; декоративные иконки — `aria-hidden="true"`.
- [ ] Видео: `muted`, `playsinline`, `loop`; при блокировке autoplay показывается кнопка Play.
- [ ] `prefers-reduced-motion: reduce` → hero-видео не автозапускается.

### 2.6 Доступность
- [ ] Skip-link работает (Tab → «Skip to content» → фокус уходит в контент).
- [ ] Видимый `:focus-visible` на всех ссылках/кнопках.
- [ ] Сравнительная таблица сохраняет семантику: роли `table / rowgroup / row / cell /
      columnheader`, подписи значений через `data-label`.
- [ ] Порядок заголовков: h1 → h2 → h3, без пропусков.
- [ ] Порядок DOM = визуальный порядок (не переставлять элементы таблицы через CSS `order`).
- [ ] Lighthouse Accessibility = **100**.

### 2.7 Производительность (бюджет)
- [ ] Первичная загрузка (HTML+CSS+JS+шрифты+первый экран) ≤ **1 МБ** на 390px.
- [ ] LCP ≤ 2.5 s (Fast 4G), CLS ≤ 0.1, INP ≤ 200 ms.
- [ ] Нет запросов изображений галереи до скролла к секции решений.
- [ ] Шрифты: `font-display: swap`, критичные — preload; Goodly — WOFF2.

## 3. Матрица ручных проверок по устройствам

| Устройство / браузер | Что проверяем отдельно |
|---|---|
| iPhone (Safari) | autoplay hero (Low Power Mode), `100vh`/safe-area, свайп слайдера, `tel:`/`mailto:` |
| Android (Chrome) | шрифты, отклик меню, свайп, отображение WebP |
| Samsung Internet | таблица-карточки, шрифты, скролл |
| iPad (Safari, 768) | таблица остаётся таблицей, сетки 2+1 |
| Desktop 1440 | регресс: таблица-таблица, точки слайдера, hero 78vh |

## 4. Чек-лист регрессии этого проекта

- [ ] Hero: высота ~78vh на 1440, на мобильных — авто; видео 16:9 без CLS.
- [ ] Trust bar: цифры белые, юниты оранжевые, «Top 3» не разъезжается.
- [ ] Zero-Emission / Boarding: 3 карточки, на мобильных — 1 колонка, без пустых ячеек.
- [ ] Сравнение: карточки на ≤720, подписи CONVENTIONAL / 3S / AIRBRIDGE®, полоса AirBridge.
- [ ] Слайдеры: счётчик «N / M», свайп, автопрокрутка 4 с, активный кадр не мигает.
- [ ] Recognition: метрики в один ряд, награды — компактные строки.
- [ ] Футер: Company/Solutions в 2 колонки, Contact на всю ширину, ~676px высоты.
- [ ] ISO-блок и юридическая строка не переносятся уродливо.

## 6. Известные ограничения

- Lighthouse скрывает блоки с `opacity: 0` (reveal-анимации), поэтому строгий аудит делается на
  временной копии с принудительно видимыми блоками.
- Тесты проводились в Chrome-эмуляции; реальные iOS/Android устройства нужно проверять отдельно.
- Скринридер-тест (NVDA/VoiceOver) для карточного режима таблицы формально не проводился.
