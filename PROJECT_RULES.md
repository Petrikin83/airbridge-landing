# PROJECT_RULES.md — Правила проекта AirBridge Landing

## 1. Цель проекта
Премиальная маркетинговая воронка (Landing Page) для технологии **AirBridge®** компании
**CDC — Cableway Development Company**. Задача страницы — эффектно презентовать технологию,
вызвать максимальное доверие B2B-заказчиков и довести их до целевого действия:
переход на головной сайт **https://cdc.company/** или отправка заявки на расчёт проекта.

## 2. Барьер безопасности (ЖЁСТКОЕ ОГРАНИЧЕНИЕ)
- **D:\Clone_CDC — ТОЛЬКО ДЛЯ ЧТЕНИЯ (READ-ONLY).**
- Категорически запрещено создавать, редактировать, удалять или перемещать **любые** файлы
  в `D:\Clone_CDC`.
- Из `D:\Clone_CDC` можно только **читать** стили, скрипты, шрифты, разметку и графику.
- Все новые файлы создаются **строго** внутри `D:\Airbridge_NEW_DeepSeek`.

## 3. Стандарты вёрстки
1. **Семантика** — корректные HTML5-теги: `<header>`, `<nav>`, `<main>`, `<section>`,
   `<article>`, `<figure>`, `<footer>`, `<address>`.
2. **Чистый HTML/CSS/JS** — без сборщиков и фреймворков (vanilla). Никаких jQuery-зависимостей
   в собственной логике лендинга (вся интерактивность — нативный JS).
3. **БЭМ-подобная система имён** классов: `ab-` префикс (AirBridge) + блок/элемент/модификатор.
   Пример: `.ab-hero`, `.ab-hero__title`, `.ab-button--primary`.
4. **Отзывчивость** — mobile-first, брейкпоинты: 480 / 768 / 980 / 1280 px.
5. **Доступность (a11y)** — семантические заголовки по иерархии, `alt` у изображений,
   `aria-label` у интерактивных элементов, видимый фокус, контраст текста ≥ WCAG AA.
6. **Производительность** — ленивая загрузка медиа (`loading="lazy"`, `preload="none"` для
   фонового видео, `poster` для видео), сжатые изображения, локальные шрифты (без внешних CDN).
7. **Без внешних зависимостей** — все шрифты/иконки/стили локальны (в `./assets/`), чтобы
   лендинг работал офлайн и на GitHub Pages.

## 4. Чистота кода
- Отступы: 2 пробела (HTML/CSS/JS).
- Кодировка: UTF-8.
- Комментарии — только там, где они добавляют смысл (секции, неочевидная логика).
- Никаких `!important` без крайней необходимости.
- CSS-переменные выносятся в единый файл токенов `assets/css/cdc-tokens.css`.
- JS: один файл `assets/js/main.js`, разбитый на короткие самодокументирующиеся функции.

## 5. Порядок работы (двухэтапный алгоритм)
1. **ЭТАП 1** — организация материалов, аудит, извлечение UI-кита CDC, подготовка
   системных документов, презентация концепта. **СТОП-ТОЧКА** — ждём одобрения.
2. **ЭТАП 2** — вёрстка `index.html`, интеграция JS, `git init` + коммит, локальный сервер
   на порту 8085, финальное обновление `MEMORY.md`.

## 6. Запреты
- Не трогать `D:\Clone_CDC`.
- Не верстать `index.html` до одобрения концепта на Этапе 1.
- Не подключать внешние CDN/счётчики/трекеры (аналитика — только по явному запросу).
- Не добавлять зависимости, которых нет в проекте.
