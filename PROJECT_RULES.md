# PROJECT_RULES.md — Правила проекта AirBridge Landing

> **СИСТЕМНОЕ ПРАВИЛО (UI/UX):** при любом аудите UI/UX фронтенда и правках стилей
> **строго руководствоваться правилами из файла `.skills/apple-design.md`**.
> Правило распространяется на все задачи — от мелкой правки CSS до рефакторинга скриптов.

## 1. Цель проекта
Премиальная маркетинговая воронка (Landing Page) для технологии **AirBridge®** компании
**CDC — Cableway Development Company**. Задача страницы — эффектно презентовать технологию,
вызвать максимальное доверие B2B-заказчиков и довести их до целевого действия:
переход на головной сайт **https://cdc.company/** или отправка заявки на расчёт проекта.

## 3. Стандарты вёрстки
1. **Семантика** — корректные HTML5-теги: `<header>`, `<nav>`, `<main>`, `<section>`,
   `<article>`, `<figure>`, `<footer>`, `<address>`.
2. **Чистый HTML/CSS/JS** — без сборщиков и фреймворков (vanilla). Никаких jQuery-зависимостей
   в собственной логике лендинга (вся интерактивность — нативный JS).
3. **БЭМ-подобная система имён** классов: `ab-` префикс (AirBridge) + блок/элемент/модификатор.
   Пример: `.ab-hero`, `.ab-hero__title`, `.ab-button--primary`.
4. **Отзывчивость** — mobile-first, брейкпоинты: 480 / 768 / 980 / 1280 px.
5. **Доступность (a11y)** — семантические заголовки по иерархии, `alt` у изображений,
   `aria-label` у интерактивных элементов, видимый фокус, контраст текста ≥ WCAG AA.
6. **Производительность** — ленивая загрузка медиа (`loading="lazy"`, `preload="none"` для
   фонового видео, `poster` для видео), сжатые изображения, локальные шрифты (без внешних CDN).
7. **Без внешних зависимостей** — все шрифты/иконки/стили локальны (в `./assets/`), чтобы
   лендинг работал офлайн и на GitHub Pages.

## 4. Чистота кода
- Отступы: 2 пробела (HTML/CSS/JS).
- Кодировка: UTF-8.
- Комментарии — только там, где они добавляют смысл (секции, неочевидная логика).
- Никаких `!important` без крайней необходимости.
- CSS-переменные выносятся в единый файл токенов `assets/css/cdc-tokens.css`.
- JS: один файл `assets/js/main.js`, разбитый на короткие самодокументирующиеся функции.

## 5. Порядок работы (двухэтапный алгоритм)
1. **ЭТАП 1** — организация материалов, аудит, извлечение UI-кита CDC, подготовка
   системных документов, презентация концепта. **СТОП-ТОЧКА** — ждём одобрения.
2. **ЭТАП 2** — вёрстка `index.html`, интеграция JS, `git init` + коммит, локальный сервер
   на порту 8085, финальное обновление `MEMORY.md`.

## 6. Python-скрипты (scripts/)

1. **Общий слой** — `scripts/_lib.py` (`ROOT`, `path()`, `rel()`, `enable_utf8()`, `read_text()`,
   `write_text()`, `file_kb()`, `iter_files()`). Не дублировать эти функции в скриптах.
2. **Контракт запуска**: `main() -> int` + `if __name__ == "__main__": sys.exit(main())`.
   Коды: `0` — успех, `1` — проверка не прошла, `2` — нет входных данных/зависимостей.
3. **Никаких жёстких путей** (`D:\...`) в активных скриптах: только `_lib.path(...)` и переменные
   окружения (`CDC_SITE`). Скрипты с жёсткими путями — только в разделе «Архивные».
4. **UTF-8 вывод** обязателен (`enable_utf8()`), иначе Windows-консоль падает на `×`/`°`.
5. **Новый активный скрипт** добавляется в таблицу `scripts/README.md`; одноразовый — в «Архивные».
6. Перед коммитом: `python scripts/run_checks.py` и `node --check assets/js/main.js`.

## 8. Дизайн-стандарт Apple (обязательно)

1. Источник правды по UI/UX — **`.skills/apple-design.md`** («Apple Design Manifest by Emil Kowalski»,
   7 правил). Файл не переписывается «по вкусу»: изменения — только по явному запросу заказчика.
2. Чек-лист соответствия (проверяется на каждой UI-правке):
   - **1. Direct Manipulation** — отклик на `pointerdown`, перетаскивание 1:1 (Pointer Events +
     `setPointerCapture`), никакой «анимации только по завершении жеста».
   - **2. Spring Physics** — никаких выдуманных фиксированных длительностей: `damping 1.0` /
     `response 0.3s` для поповеров и шторок (в т. ч. мобильного меню), `response 0.4s` для
     перетаскиваемых поверхностей (слайдер); `damping 0.8` (лёгкий overshoot) — только там,
     где жест нёс momentum (флик/свайп).
   - **3. Rubber-banding** — на границах прогрессивное нелинейное сопротивление, без жёсткого стопа.
   - **4. Translucent Chrome** — навигация и меню: `backdrop-filter: blur() saturate()`, контент
     прокручивается под слоем; обязателен непрозрачный fallback (`@supports not (...)`).
   - **5. Frame-level Smoothness** — анимируются только `transform`/`opacity`, с `will-change`.
   - **6. Reduced Motion** — `prefers-reduced-motion`: пружины заменяются на быстрые 150 мс
     opacity-фейды, автопрокрутка слайдеров отключается.
   - **7. High Contrast** — `prefers-contrast: more`: полупрозрачные тени заменяются чёткой
     рамкой 1px.
3. Запрещено добавлять «декоративные» анимации, не описанные манифестом (параллакс, бесконечные
   пульсации, конфетти): движение объясняет состояние, а не развлекает.
4. Перед коммитом UI-правок: `python scripts/run_checks.py` + `node --check assets/js/main.js`;
   для визуальных изменений — проверка на 360 / 390 / 768 / 1440 px.
